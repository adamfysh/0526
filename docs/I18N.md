# Bilingual (EN/FR) rules

English is unprefixed, French lives under `/fr/`. Routes are `src/pages/[...lang]/*.astro`.
All copy is in `src/i18n/pages/<page>.ts` as `{ en, fr }` with `fr: typeof en`, so TypeScript
(`npx astro check`) flags a missing French key. Shared nav/footer/head text is in `src/i18n/ui.ts`.

## Rule: one change, two languages

Any fix to a figure, date, count or sentence is made in **both** `en` and `fr` in the same
change. Shared figures live in one place so they are fixed once:

- `src/i18n/pages/dataTiers.ts`: tier names, tier shares, row counts
- `src/i18n/pages/changelog.ts`: correction entries (add the same entry to both arrays, update the hero count and "most recent")
- `src/i18n/pages/policy.ts`: the policy hero count must match the changelog

## Checks before every deploy

```
npm run build
npm run check:i18n
```

`check:i18n` fails if a page in `TRANSLATED_PATHS` is missing in either language, contains an
em-dash or "undefined", is not `lang="fr"`, is identical in both languages, or shows different
numbers in EN and FR (a figure fixed in one language only). x and x*1000 are treated as equal
($2.15T vs 2 150 Md$).

## Adding a page

1. Create `src/i18n/pages/<page>.ts` and `src/pages/[...lang]/<page>.astro` (copy `about.astro`).
2. Add the path to `TRANSLATED_PATHS` in `src/i18n/index.ts`. Until then links to it stay English and the switcher stays hidden.
3. Build, then run `check:i18n`.

## French style

Non-breaking space before `: ? ! % ;` and inside « ». Thousands "3 774", decimals "36,5 Md$".
No em-dashes in either language. Terms: point de passage obligé, indice de risque portuaire,
coût de déroutement, valeur à risque, niveaux Déclaré / Recoupé / Estimé.
Public English copy uses no contractions.

## Commercial layer

`COMMERCIAL` in `src/config.ts` gates all sales content (English only). When it is switched on
for the French site, that copy needs translating too (open item D).


## CAPE tool (public/cape.html)
- Not an Astro page: French is switched by `?lang=fr` and lives in `public/cape-i18n.js`.
- Add a string: if it is static HTML or a whole rendered text node, add exact English -> French to `STATIC` or `DYN`. If a sentence has interpolated values, write it with `LX(en, fr)` in `cape.html`.
- Data that comes from a feed carries `{en, fr}` at source (fleet notes, port notes).
- `python3 scripts/check-cape-i18n.py` must pass before a CAPE change is deployed.

## Static public pages and non-Astro pages (post-build)

Pages that are not `[...lang]` routes (analysis articles, `lng-compare`, `cascade`, `cascade-plus`, the Sankeys, `viz/*`) get French from `scripts/fr-postbuild.mjs`, which reads a dictionary per page.

- Dictionary: `src/i18n/articles/<path with / as __>.json`, shape `{path, meta:{title,description}, pairs:[[enKey, frHtml]], js:[[enSubstring, frSubstring]]}`. Register the page in `_required.json` and in `TRANSLATED_PATHS` (`src/i18n/index.ts`), which drives hreflang and the rewriting of internal links and iframes to `/fr/...`.
- Tools: `scripts/fr-extract.mjs <rel> <keys.json>` lists the blocks to translate; `scripts/fr-merge.mjs <rel> <keys.json> <fr.json> [meta]` upserts them. A missing dictionary or an untranslated block fails the build.
- Text built by inline scripts: `js` pairs are applied as plain substring replacement over inline script text only (external or hoisted JS is untouched). A pair whose English side is not found fails the build as `@js:`, so remove pairs already consumed by an earlier, longer pair. Use curly apostrophes in French strings, never a raw `'`.
- Numbers must reproduce the English digits (`npm run check:i18n`). Money in prose: "55 millions de dollars", "28 dollars le baril".
- Iframes whose `src` is a translated path are pointed at the French copy automatically.

Known gaps: `NARROWS-CORRIDORS.js` and `NARROWS-RATES.js` labels stay English on French pages; CASCADE+ CSV/ledger export strings and `title` attributes stay English; `primap.html` has its own `?lang=fr` mechanism.
